==============================================================================
 ЛАБ 9 — Миграции Entity Framework Core
==============================================================================

ЗАЧЕМ НУЖНЫ МИГРАЦИИ
--------------------
Code First: схему БД описывают C#-классы (папка Entities/). Когда модель
меняется (добавили поле, новую сущность, связь), БД нужно привести в
соответствие. Миграция — это автогенерируемый C#-класс с методами Up()
(применить изменение) и Down() (откатить). Миграции версионируют схему
и позволяют обновлять БД без потери данных и без ручного SQL.

В НАШЕМ ПРОЕКТЕ
---------------
БД WatchShopDB уже создана скриптом Database/InitDatabase.sql (лаб 8).
EF Core Code First работает с этой готовой БД — сущности из Entities/
смаплены на существующие таблицы. Поэтому для работы приложения
миграции выполнять НЕ обязательно: схема уже есть.

Но ТЗ требует уметь показать миграции. Ниже команды.

СОЗДАТЬ ПЕРВУЮ МИГРАЦИЮ
-----------------------
Tools → NuGet Package Manager → Package Manager Console, затем:

   Add-Migration InitialCreate

EF просканирует WatchShopDbContext + Entities/, сравнит с текущим
снимком модели (его пока нет) и сгенерирует папку Migrations/ с
классом <timestamp>_InitialCreate.cs — там CreateTable(...) для
каждой сущности в методе Up().

ПРИМЕНИТЬ МИГРАЦИЮ К БД
-----------------------
   Update-Database

Если БД ещё нет — EF создаст её и все таблицы.
Если БД уже есть (наш случай — создана скриптом) — выполнять эту
команду НЕ нужно, иначе EF попытается создать уже существующие
таблицы и упадёт. Для защиты достаточно показать сгенерированный
класс миграции и объяснить Up()/Down().

ПОСЛЕДУЮЩИЕ ИЗМЕНЕНИЯ
---------------------
Поменял сущность (например, добавил поле в WatchEntity):

   Add-Migration AddedNewField
   Update-Database

EF сгенерирует только delta (ALTER TABLE ADD COLUMN ...), не пересоздавая
всю БД. Данные сохраняются.

ОТКАТ
-----
   Update-Database <ИмяПредыдущейМиграции>

выполнит Down() последней миграции — откатит изменение.

ПОЛЕЗНЫЕ КОМАНДЫ
----------------
   Get-Migrations               — список миграций
   Remove-Migration             — удалить последнюю (если не применена)
   Script-Migration             — сгенерировать SQL-скрипт миграции

dotnet CLI аналоги (из папки проекта):
   dotnet ef migrations add InitialCreate
   dotnet ef database update
   dotnet ef migrations remove
